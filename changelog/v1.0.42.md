# RxFHIR v1.0.42

## Added

### Validator-friendly Document Bundle export

`assembleDocumentBundle` now accepts `mode: 'submit' | 'export'` and a new
`toSelfContainedExportBundle()` converter normalizes any bundle (including
HAPI-retrieved ones) into a self-contained form before download. The
exported JSON now passes the TW Core EMR `Bundle-EP` validator without
manual editing.

- every entry uses a `urn:uuid:<v4>` `fullUrl` and matching internal
  references, so external validators can resolve refs inside the bundle
  alone (no server resolution required)
- every reference carries `Reference.type` so slice discriminators of the
  form `discriminator: { type: 'profile', path: 'entry.resolve()' }` can
  pick the right choice without resolution — fixes the long list of
  `Reference_REF_CantMatchChoice` errors
- HAPI-injected `meta.source` / `versionId` / `lastUpdated` are stripped
  on the bundle and on every entry resource
- extensions whose definitions are absent from the current TW Core EMR
  validator are dropped on export (currently
  `Extension-TotalDuration`; the same data is preserved in
  `MedicationRequest.dispenseRequest.expectedSupplyDuration`)

The HAPI submit path is unchanged (`mode: 'submit'`, default) — HAPI-0505
compatibility is preserved.

### IG cardinality and content fillers

The bundle assembler now injects fields the wizard does not yet collect,
so the exported bundle satisfies TW Core EMR profile cardinality:

- Patient: `extension[]` includes `person-age` (`twcore` namespace),
  derived from `birthDate`
- Organization: fallback `telecom` and `address` when missing
- Encounter: default `serviceType` (HL7 `service-type` `124` General
  Practice)
- Condition: `category` (`encounter-diagnosis`), `note`, and an
  ICD-10-CM coding using the canonical American-spelling display
- Observation: `category` (Vital Signs) and `valueQuantity.code` mapped
  through `UCUM_UNIT_MAP` (`mmHg` → `mm[Hg]`, `beats/min` → `/min`,
  `Cel`, `mg/dL`, drug-form annotations like `{tablet}`, etc.)
- MedicationRequest: 2nd identifier (prescription number),
  `category` (`OUTPATIENT`), `insurance` reference to Coverage,
  `dosageInstruction.timing.repeat` derived from QD / BID / TID / QID /
  PRN, `dispenseRequest.validityPeriod` /
  `numberOfRepeatsAllowed` / `quantity` defaults

`canonicalizeDisplays()` walks every resource and rewrites
`Coding.display` to en-US canonical strings for known LOINC, ICD-10,
ICD-10-CM, SNOMED, ATC, v2-0203, v3-orderableDrugForm, v3-ActCode,
observation-category, and condition-category codes — so the validator's
`TerminologyEngine` stops complaining. Localized Chinese labels remain in
`CodeableConcept.text` for the in-app UI.

### Composition section LOINCs aligned with the IG slice discriminators

`Composition.section` now uses LOINC codes that match the TW EMR
`Composition-EP` slice discriminators so each required slice resolves:

- `Composition.section:Coverage` → `48768-6` Payment sources Document
- `Composition.section:Condition` → `29548-5` Diagnosis Narrative
- `Composition.section:MedicationPrescribed` → `29551-9` Medication
  prescribed Narrative

### Bundle ID sort in Consumer results

The Consumer results sort dropdown adds two new options — Bundle ID
(newest → oldest) and Bundle ID (oldest → newest) — alongside the
existing date and patient-name choices. Sorting uses `Intl.Collator` with
`numeric: true` so HAPI's numeric Bundle IDs (e.g. `132015363`) order
naturally; UUID-style IDs fall back to lexicographic comparison.

## Changed

### Patient identifier moved from `SB` Student Number to `MR` Medical record number

The Creator Patient form previously used `v2-0203#SB` (canonical en-US
display "Social Beneficiary Identifier") on the
`https://www.moe.edu.tw/student-id` system. The semantics did not match
the demo intent (a hospital prescription system), and the validator
enforced the en-US display lookup, producing terminology mismatches.

- `system` is now `https://rxfhir.app/fhir/medical-record-number`
- `type.coding` is now `v2-0203#MR` ("Medical record number")
- the same change is mirrored in `findOrCreate` lookup queries and the
  Feature Showcase snapshot's `PATIENT_IDENTIFIER_SYSTEM`

The Patient ID values themselves are unchanged; MR has no required
format under FHIR, so existing 9-digit values (`142216009`) and
mixed-format values (`S1101001`) remain valid.

### `dateTime` values now always carry a timezone

`toFhirDateTime` is now applied to `Composition.date`,
`Encounter.period.start/end`, `Observation.effectiveDateTime`,
`Condition.recordedDate`, and `MedicationRequest.authoredOn` during
bundle normalization, so the TW Asia/Taipei offset (`+08:00`) is
attached and `If a date has a time, it must have a timezone` errors
disappear.
