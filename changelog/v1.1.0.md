# RxFHIR v1.1.0

## Added

- Converter module: a dedicated sidebar workspace that converts FHIRfox-style competition problem JSON into TW Core (twcore) compliant FHIR collection Bundles for the conference Gazelle/Prism validator, covering 11 resource types (Patient, Organization, Encounter, Condition, Practitioner, PractitionerRole, AllergyIntolerance, Observation, Procedure, DiagnosticReport, MedicationRequest) with urn:uuid references, generated narratives, UCUM quantities, and per-resource TW Core profiles
- Built-in competition code dictionary mapping opaque codes (Cond-/serviceType/PR-/Spec-/Qual-/Med-/Lab-/Rep-/Tim-/Route-/Perf-/bodySite) to standard SNOMED CT, LOINC, and HL7 terminology
- Learn-from-errors workflow: paste Gazelle validation errors to auto-derive new code mappings via the generated bundle's provenance, persisted locally, with a clear-dictionary action; built-in mappings take precedence over learned ones
- OAuth 2.0 client-credentials authentication for FHIR servers behind an authorization gateway (token endpoint, client id/secret, participant token) with automatic token fetch, cache, and pre-expiry refresh; credentials can be pre-filled from a gitignored .env.local
- Main-process CORS shim so authenticated cross-origin FHIR/OAuth requests pass preflight without disabling webSecurity
- Syntax-highlighted JSON code editor and a color-highlighted Bundle preview in the Converter

## Changed

- FHIR error formatting now surfaces error-severity OperationOutcome issues ahead of best-practice (dom-6) warnings
- Individual resource POST/PUT now applies the same TW Core EMR hardening (narrative, required cardinality) used for bundle export

## Fixed

- Conference FHIR server submissions now attach OAuth + participant headers across all request paths, resolving the false "connection failed" status
