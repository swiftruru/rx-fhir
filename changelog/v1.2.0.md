# RxFHIR v1.2.0

## Added

- Converter competition-proof workspace: a pre-submit conformance checklist (Bundle.type=collection, Bundle and per-entry meta.profile, resource counts/types with optional case-summary expected-count comparison)
- Converter local-code to standard-code mapping table, built from the bundle provenance, listing each competition code and the SNOMED/LOINC/HL7 code it converted to (unmapped codes flagged)
- In-app FHIR request inspector for the Converter's submit, $validate, and OAuth token-exchange calls, with a reveal-full-token toggle so Authorization and X-Participant-Token can be screenshotted
- One-click proof artifacts in the Converter: download the converted Bundle JSON, capture a PNG screenshot of the current view (new capture:screenshot IPC), and export a per-case HTML proof report (counts + conformance + code table + submit result) that prints to PDF
- tools/connectathon-helper: a standalone TypeScript/Node + Playwright CLI that automates the TWCAT/Gazelle connectathon proof loop (token, convert, upload, codemap, screenshot, record, report to Markdown/PDF), reusing the App's pure domain logic; Gazelle/FHIRfox web steps are record-only
- docs/conformance: a FHIR R4 CapabilityStatement and a written System Summary for connectathon registration

## Changed

- The request inspector now masks Authorization / X-Participant-Token at render time (not at store time) so the values can be revealed on demand; Creator stays masked by default
- COMPETITION_CODE_MAP is exported so the App and the connectathon CLI share one local-code dictionary

## Fixed

- /converter requests are now tagged as their own module and no longer fall through to the generic app bucket, so they surface only in the Converter inspector
